## 2. Key Findings from the CPI Audit (`docs/CPI_AUDIT.md`)

### 2.1 The Stale "2.560 CPI" Investigation
* **Origin**: In earlier documentation drafts, a table listed a speculative CPI stack totaling 2.560 (Base 1.0, RAW 0.25, Branch 0.35, Structural 0.18, I-Cache 0.42, D-Cache 0.31, Page Walks 0.05).
* **Investigation Result**: That table was typed by hand before the simulator pipeline models were completed.
* **Empirical Reality**: When actually measured across all benchmarks with code generated by `tools/audit_cpi.cpp`:
  * Under **`ideal`** memory preset (1-cycle memory), 4-stage pipeline CPI is **$1.02 - 1.15$**, and 6-stage pipeline CPI is **$1.10 - 1.25$**.
  * Under **`modern`** memory hierarchy, steady-state CPI is **$1.12 - 1.35$**.

### 2.2 Cold-Start vs. Steady-State Distinctions
* For tiny benchmarks ($N < 30$ instructions), cold-start compulsory cache misses and initial page table walks occur once on process startup. When divided across only 15 instructions, compulsory misses inflate apparent cold CPI to $2.0 - 3.5$.
* On extended benchmarks (`*_long.s`), the working set fits into the 32 KB L1 cache ($>99.5\%$ hit rate). The steady-state CPI stabilizes at **$1.05 - 1.18$**, proving the architectural health of the pipeline.

## 3. 4-Stage vs. 6-Stage Execution Speedup Analysis
While the 4-stage pipeline has a lower CPI than the 6-stage pipeline due to shorter branch and load penalties, **the 6-stage pipeline wins substantially in wall-clock execution time**:

$$\text{Execution Time } T = \text{Instruction Count} \times \text{CPI} \times t_{\text{clk}} = \frac{\text{Instruction Count} \times \text{CPI}}{\text{Clock Frequency } f}$$

* **4-Stage Core**: $f = 500\text{ MHz} \implies t_{\text{clk}} = 2.00\text{ ns}$.
  $$T_{\text{4-stage}} = 168,044 \times 1.125 \times 2.00\text{ ns} = \mathbf{378.1\text{ }\mu\text{s}}$$
* **6-Stage Core**: $f = 800\text{ MHz} \implies t_{\text{clk}} = 1.25\text{ ns}$.
  $$T_{\text{6-stage}} = 168,044 \times 1.131 \times 1.25\text{ ns} = \mathbf{237.6\text{ }\mu\text{s}}$$
* **Speedup**:
  $$\text{Speedup} = \frac{378.1\text{ }\mu\text{s}}{237.6\text{ }\mu\text{s}} = \mathbf{1.59\times \text{ faster (a } 59\% \text{ speedup!)}}$$

The 6-stage processor finishes the program 59% faster in wall-clock time because splitting `OF` into `ID` and `RF` allows the clock frequency to scale from 500 MHz to 800 MHz!
